## Findings (verbatim)

## Verdict: NO GO

**NO GO for implementation as written.** The direction is defensible, but several proposed contracts conflict with the current engine: golden neutrality requires a compatibility encoding, `sharedFree` cannot directly validate existing reservations, staffing changes need a new rebooking lifecycle, and teleradiology needs persistent reader state across midnight. The economic targets are plausible hypotheses, not yet demonstrated; some stated exploit guards are false under current payroll and metrics semantics. Resolve these contracts and run the sustainable-scenario feasibility experiment before building the actions and TUI. This review used source inspection and arithmetic over the supplied inputs/results; I did not modify files or run new simulation experiments.

## Findings

1. **High — §§1.1, 6.2, 6.5, 9: “unchanged outcomes” does not currently permit changed state encodings.**  
   **Evidence:** [digest.go:41](/tmp/dt-review.VdCTC9/internal/sim/digest.go:41) excludes configuration pointers but reflectively hashes other struct fields; slices and arrays include their lengths. Adding even empty roster-version fields changes the state digest. Adding accounts changes `[numAccounts]` arrays and the baseline account list ([ledger.go:121](/tmp/dt-review.VdCTC9/internal/sim/ledger.go:121), [evaluation.go:65](/tmp/dt-review.VdCTC9/internal/sim/evaluation.go:65)). Golden comparison ignores only `.engine`, and compares all five digests and new/missing fields ([result.go:330](/tmp/dt-review.VdCTC9/internal/session/result.go:330)). Replay also refuses engine mismatches by default and compares action results exactly ([record.go:371](/tmp/dt-review.VdCTC9/internal/session/record.go:371)).  
   **Why it matters:** Step 1 can fail all four goldens without changing gameplay; new scorecard fields can independently fail them.  
   **Change:** Specify a versioned canonical encoding and legacy verification/output path before step 1. Preserve V0.1 account/event numbers, action serialization and messages. Keep old references unchanged and verify their complete legacy projection; separately test V0.2 state coverage. Explicitly decide how V0.1 replay passes the engine-version gate.

2. **High — §6.3: `sharedFree` is an insertion predicate, not an existing-schedule validator.**  
   **Evidence:** [demand.go:273](/tmp/dt-review.VdCTC9/internal/sim/demand.go:273) checks existing reservations **plus one proposed slot**. It returns true immediately for `!s.shared`, skips unstaffed stretches of existing reservations, and does not exclude the proposed slot if that slot already has an appointment. `firstFit` separately requires `s.why == slotOK` before calling it ([demand.go:590](/tmp/dt-review.VdCTC9/internal/sim/demand.go:590)).  
   **Why it matters:** Calling it on occupied slots can count the appointment twice; calling it alone can miss missing staffing or contrast supervision. When two bookings compete for one remaining technician, “those that fail” does not uniquely identify which booking survives.  
   **Change:** Define a deterministic reservation-reconciliation algorithm: recompute coverage, validate individual bookability, retain reservations in an explicit order using the existing insertion predicate on a temporary reservation set, then reoffer displaced appointments. Specify survivor order separately from rebooking order.

3. **High — §§5.2–5.3, 6.3: there is no suitable existing staffing-rebooking operation.**  
   **Evidence:** Patient cancellation frees the slot but increments cancellation counts and may end the order according to a cancellation-specific draw ([demand.go:673](/tmp/dt-review.VdCTC9/internal/sim/demand.go:673)). `reschedule` increments the attempt and offers tomorrow but retains the old slot ([flow.go:232](/tmp/dt-review.VdCTC9/internal/sim/flow.go:232)). The invariant currently treats every appointment except `apptCancelled` as holding a slot ([demand.go:789](/tmp/dt-review.VdCTC9/internal/sim/demand.go:789)). `offer` measures tolerance relative to its supplied `earliest` argument.  
   **Why it matters:** Reusing either path misclassifies patient behavior or leaves stale reservations. Resetting `earliest` can repeatedly renew tolerance; incrementing attempts changes cancellation/no-show/exam draws. Reoffering from the original requested date can also move a displaced future appointment earlier unexpectedly.  
   **Change:** Add an explicit practice-initiated displacement state/reason and specify slot release, stale-event handling, attempt identity, earliest replacement date, tolerance anchor and history. Release the displaced set before reoffering it. Preview coverage consequences without exposing latent patient acceptance.

4. **High — §§6.1–6.2: appending employees requires a state-model migration, not just growing `emps`.**  
   **Evidence:** Employees hold pointers into `cfg.Employees` ([world.go:83](/tmp/dt-review.VdCTC9/internal/sim/world.go:83)); plans and coverage also read that configuration ([config.go:352](/tmp/dt-review.VdCTC9/internal/sim/config.go:352)). Metrics initialize employee arrays once, then index both historical and current snapshots using the current configuration’s employee count ([metrics.go:75](/tmp/dt-review.VdCTC9/internal/sim/metrics.go:75), [metrics.go:369](/tmp/dt-review.VdCTC9/internal/sim/metrics.go:369)).  
   **Why it matters:** An append can leave configuration pointers referencing an older backing array; historical snapshot subtraction can panic. Recomputing an old summary after hiring could differ from a previously cached summary. Mutating configuration also bypasses fields intentionally excluded from state hashing.  
   **Change:** Specify an authoritative employee registry separate from immutable scenario configuration, stable indices and IDs, date-aware accessors, and historical metric semantics for employees absent from a snapshot. Test hiring after historical summaries have been both read and left unread.

5. **Medium — §§5.3, 6.1: roster-version composition and batch behavior are unspecified.**  
   **Evidence:** Existing batches apply actions sequentially, with immediate mutations and only dispatch deferred ([actions.go:16](/tmp/dt-review.VdCTC9/internal/sim/actions.go:16)). The scenario shape supports one shift per weekday, optionally restricted to A or B—not separate A/B shifts for the same weekday ([config.go:228](/tmp/dt-review.VdCTC9/internal/sim/config.go:228)).  
   **Why it matters:** Implementers must choose what happens with duplicate effective dates, insertion before an already-approved version, replacement of future versions, and different A/B hours. A two-person roster swap can lose patients after its first action even if its final coverage is unchanged.  
   **Change:** Define version precedence, replacement/cancellation, rota anchoring and action no-ops. Either provide an atomic multi-employee staffing-plan action or document sequential displacement and provide a batch preview. Clarify the supported fortnight shape.

6. **High — §§5.3, 6.6, 8: roster and extension validation must be composed.**  
   **Evidence:** Extensions are stored as durations and added blindly by `planFor` ([actions.go:110](/tmp/dt-review.VdCTC9/internal/sim/actions.go:110)). The draft preserves one whenever it “still extend[s] a shift.” Scenario validation additionally requires `shift start + maxShiftHours` to precede midnight ([validate.go:317](/tmp/dt-review.VdCTC9/internal/scenario/validate.go:317)); the draft omits this.  
   **Why it matters:** An extension accepted against an eight-hour shift can exceed the cap after that shift becomes eleven hours. Changing the preceding or following roster can violate ten-hour rest despite each submitted pattern passing independently. New late shifts can violate accounting-close assumptions.  
   **Change:** Validate the composed timeline, including extensions, adjacent versions, both rota weeks and employment boundaries. Define exactly which extension conflicts reject the roster or cancel an approval. Preserve the existing allowance for pre-opening shifts; “room exists and is open” cannot simply mean the entire shift lies inside opening hours.

7. **High — §§5.2–5.3, 8: zero-hour rosters bypass paid notice and potentially severance.**  
   **Evidence:** Hourly wages accrue only for time actually worked ([finance.go:374](/tmp/dt-review.VdCTC9/internal/sim/finance.go:374)). The proposed roster rules impose no minimum hours; termination says employees work “their roster,” and “two weeks’ pay” has no defined basis.  
   **Why it matters:** A player can roster an unwanted employee off indefinitely, avoiding termination altogether. If severance uses the current roster, reducing hours before termination can also reduce severance to zero. A per-role cap merely postpones this strategy until replacement capacity is needed.  
   **Change:** Decide whether employment guarantees hours. Protect notice pay and severance using a frozen contractual or historical-hours basis, including benefits and treatment of overtime. Treat material contracted-hours reductions explicitly. Test zero-roster removal and terminate/recruit-at-lower-pay sequences.

8. **Medium — §§5.1–5.3, 6.2: hiring and onboarding lack enforceable lifecycle definitions.**  
   **Evidence:** “Five working days” has no minimum duration, mentor requirement or desk-shadowing rule. The code’s room and registration dispatch select eligible employees directly ([config.go:483](/tmp/dt-review.VdCTC9/internal/sim/config.go:483), [ops.go:109](/tmp/dt-review.VdCTC9/internal/sim/ops.go:109)). Scenario employee IDs need only be unique nonempty strings ([validate.go:237](/tmp/dt-review.VdCTC9/internal/scenario/validate.go:237)).  
   **Why it matters:** Five tiny shifts could finish onboarding; a shadow could accidentally register patients or staff rooms. Future roster changes can move an onboarding completion date after bookings have already used it. “Next ID E09” can collide in custom scenarios. The lifetime 64-employee cap also eventually exhausts recruitment even at low active headcount.  
   **Change:** Define onboarding in paid training hours or minimum-length attended shifts, its capacity exclusion, and whether mentor coverage is required. Specify pending-hire cancellation/termination and headcount treatment of pending, active and departed employees. Allocate collision-free IDs. Publish complete skill/pay bands; intermediate wages are dominated by the minimum unless they buy a defined recruiting benefit.

9. **High — §§5.4.1, 5.3, 8: unrestricted radiologist rosters can create free reading capacity.**  
   **Evidence:** `set_roster` does not restrict eligible roles. Reading blocks depend on roster span, while salary expense depends only on annual rate and allocation—not roster hours ([config.go:365](/tmp/dt-review.VdCTC9/internal/sim/config.go:365), [finance.go:302](/tmp/dt-review.VdCTC9/internal/sim/finance.go:302)). Allocation does not reduce on-site contrast supervision ([config.go:456](/tmp/dt-review.VdCTC9/internal/sim/config.go:456)).  
   **Why it matters:** Longer/more radiologist shifts could restore reading capacity after an allocation cut at no additional salary expense, undermining the intended coverage trade-off. Moving shifts can also eliminate evening gaps without teleradiology.  
   **Change:** Restrict V0.2 roster editing to hourly technologists/front desk, or define radiologist contractual hours and how roster changes affect salary/site commitments. State explicitly that allocation changes leave supervision presence unchanged; they should not by themselves trigger contrast rebooking.

10. **High — §6.4: teleradiology needs a distinct reader lifecycle and midnight invariants.**  
    **Evidence:** `study.by` is an employee index; claiming, completion, breach messages, observations and invariants dereference `st.emps[s.by]` ([reading.go:37](/tmp/dt-review.VdCTC9/internal/sim/reading.go:37), [reading.go:203](/tmp/dt-review.VdCTC9/internal/sim/reading.go:203)). Accounting close rejects busy employees, and midnight resets employee tasks ([flow.go:252](/tmp/dt-review.VdCTC9/internal/sim/flow.go:252), [staff.go:91](/tmp/dt-review.VdCTC9/internal/sim/staff.go:91)).  
    **Why it matters:** A special employee index is insufficient, especially for two simultaneous reads crossing midnight. Reusing employee state risks losing claims or violating closing invariants.  
    **Change:** Define a tagged reader identity and persistent remote lanes with stable lane order. Claim once during dispatch, after employed readers, never in independent concurrent handlers. Separate common report finalization from employee release/debt handling. Test simultaneous completions, window edges, midnight, accounting close and cancellation with reads in flight.

11. **High — §§5.4.2, 6.4–6.5: the contract’s operating and financial semantics are incomplete.**  
    **Evidence:** Scope `all` means studies entering the worklist inside a window in §5.4.2, while §6.4 describes claiming eligible work inside windows. These differ for a backlog present at 18:00. Cancellation has no action payload; activation notice appears only in the summary. The engine processes events before dispatch at each timestamp ([engine.go:165](/tmp/dt-review.VdCTC9/internal/sim/engine.go:165)).  
    **Why it matters:** Earlier urgent studies may become permanently ineligible under one interpretation. Handoff may or may not occupy concurrency; a site reader may or may not reclaim a transferring study. Friday-night attribution, Sunday→Monday coverage, overlapping windows and reads finishing after expiry affect both service and cost.  
    **Change:** Publish half-open absolute-time window rules, eligible-backlog rules, handoff ownership/concurrency, finish-after-close behavior, and deterministic wake events. Add cancellation/successor-contract schemas. Define activation, retainer proration, invoice/payment dates, minimum commitment, night-fee timestamp and price locking for in-flight reads.

12. **High — §§6.5, 8: payroll proration contradicts the existing hourly-pay model, and new costs lack a posting contract.**  
    **Evidence:** Payroll pays the accumulated liability on the anchored payday; hourly wages already accrue by employee/day from worked seconds ([finance.go:282](/tmp/dt-review.VdCTC9/internal/sim/finance.go:282), [finance.go:362](/tmp/dt-review.VdCTC9/internal/sim/finance.go:362)). Weekly paid time resets Monday, independently of payday ([world.go:291](/tmp/dt-review.VdCTC9/internal/sim/world.go:291)). Cash reconciliation currently accounts for receipts, payroll and AP payments ([finance.go:587](/tmp/dt-review.VdCTC9/internal/sim/finance.go:587)).  
    **Why it matters:** Additional “proration by days employed” can double-prorate hourly earnings or pay unworked days. Posting recruiting directly to cash without extending reconciliation breaks invariants. Activation after daily salary accrual would charge the wrong allocation for that day.  
    **Change:** Retain actual-time hourly accrual and anchored liability settlement, including payment after departure. Apply effective employment/allocation state before accrual. Specify each new expense’s recognition event, liability/cash counterpart, benefits treatment, idempotency key and settlement schedule.

13. **High — §§3.1, 4.2–4.3, 11: scenario feasibility must precede feature implementation.**  
    **Evidence:** The existing three-tech experiment produces **$223.2k revenue, $260.4k expense and −$37.2k profit over 30 days**; its 90-day margin is −18.6% (`results/staffing-three-techs.json`, aggregate windows). The proposed allocation saves only about $5k/month, and its stability was established at baseline volume, not the larger, higher-reading-time mix.  
    **Why it matters:** More referrals need not become completed, reported exams. The specified starting roster already includes the evening US employee that §7.1 presents as a profitable hiring decision. A profitable static scenario does not establish profitable marginal hires or an interesting action plan.  
    **Change:** Move a static-overlay feasibility sweep to step 0: source-specific demand increments, explicit rosters/templates, reading stability and marginal capacity economics. Publish the profitable remaining opportunity at takeover. Specify whether bands apply to mean, median or individual seeds, and add 90-day/steady-state acceptance. Preserve the explicit “report failure rather than force parameters” rule.

14. **High — §8: the claimed teleradiology price guard is unsupported by the proposed numbers.**  
    **Evidence:** Employed reading costs roughly **$55k/month including benefits**, or about **$40/report** at the measured 1,379 monthly reports. The illustrative outsourced fees average approximately **$29.31/read** using the baseline exam mix, before retainers/night differential.  
    **Why it matters:** The statement that per-read fees exceed salaried cost per read is false as an aggregate comparison. Whether minimum allocation plus `all` dominates depends on the *marginal* studies outsourced, retained on-site salary, windows, concurrency and service limits. Site-first ordering does not establish the guard.  
    **Change:** Remove the asserted guard pending a measured allocation×contract sweep. Compare avoidable salary against incremental contract cost at equal workload and service constraints. Permit outsourcing to be economically attractive if justified; do not manufacture a price solely to prevent it.

15. **High — §§4.3, 7.3, 8: the evaluation horizon rewards cost cutting and largely excludes hiring benefits.**  
    **Evidence:** A normal tech hire begins at day 28 and then shadows five working days: no productive contribution in T30. Roster notice from Tuesday October 13 reaches Monday November 2, day 20. The evaluation records postings within its endpoint and has no future-commitment charge ([evaluation.go:47](/tmp/dt-review.VdCTC9/internal/sim/evaluation.go:47)).  
    **Why it matters:** A T30 “good plan” will principally exploit existing staff, reading allocation and policies. Notice does not guarantee severance falls inside an arbitrary evaluation window. More importantly, zero-hour rosters and late allocation cuts can save current costs while pushing lost access/backlog beyond it. A report-only scorecard imposes no service constraint on margin optimization.  
    **Change:** Use T30 for initial-state characterization and a longer management horizon, with a defined follow-up tail and outstanding obligations/backlog report. Define service eligibility gates or Pareto objectives for “good”; keep financial results unaltered. Test endpoint-shifted plans. Do not assert that a bad plan must lose money when acceptance only requires it to underperform.

16. **High — §§6.3, 7.2: demand and reporting metrics need explicit cohorts and censoring.**  
    **Evidence:** `LostRate` currently divides loss events in the period by orders received in the period ([metrics.go:309](/tmp/dt-review.VdCTC9/internal/sim/metrics.go:309)). `countOrder` deliberately separates walk-in-origin bookings ([demand.go:192](/tmp/dt-review.VdCTC9/internal/sim/demand.go:192)). Runtime TAT includes unfinished studies at current age, while calibration priority percentiles use completed studies only ([metrics.go:441](/tmp/dt-review.VdCTC9/internal/sim/metrics.go:441), [calib_test.go:389](/tmp/dt-review.VdCTC9/internal/sim/calib_test.go:389)).  
    **Why it matters:** Displacing inherited bookings can make period losses exceed period receipts. Counting every displaced walk-in appointment as referral loss reverses the 18.1 correction. First-appointment lead time conceals later displacement. Routine median alone can conceal a starving minority; completed-only percentiles can improve when difficult studies never finish. “Claimed on a later date” establishes overnight waiting, not its cause.  
    **Change:** Separate unique-order receipt cohorts, inherited-booking displacement cohorts and booking-attempt events. Preserve origin and structured reasons. Report original/current appointment delay and unresolved counts. Publish completed TAT distributions alongside unfinished counts, oldest ages and overdue fractions by priority/modality, including soon. Define overnight waiting separately from proven lack of reader coverage.

17. **Medium — §§5.3, 7.2, 8: overtime and skipped-break scores can be improved without improving working conditions.**  
    **Evidence:** Overtime metrics measure time beyond the rostered end ([metrics.go:113](/tmp/dt-review.VdCTC9/internal/sim/metrics.go:113)); payroll premiums measure weekly paid time above 40 hours ([finance.go:366](/tmp/dt-review.VdCTC9/internal/sim/finance.go:366)). Skipped breaks count only a scheduled break that could not be taken ([staff.go:177](/tmp/dt-review.VdCTC9/internal/sim/staff.go:177)).  
    **Why it matters:** Six ten-hour rostered days can show zero schedule-overrun overtime while incurring twenty premium hours. Removing breaks makes skipped-break counts zero. Extensions below 40 hours are paid at base rate, so §8’s blanket “extensions are costlier; overtime ×1.5” is incorrect.  
    **Change:** Report scheduled hours, worked hours, weekly premium hours and roster overruns separately. Define minimum break requirements or a break-entitlement metric. Treat splitting work among genuine part-time employees as an explicit economic choice, rather than assuming every extension is intrinsically expensive.

18. **Medium — §§4.2–4.3: shorter US slots and inherited calibration targets are not specified consistently.**  
    **Evidence:** Templates contain explicit starts/counts ([established.json:150](/tmp/dt-review.VdCTC9/scenarios/base/established.json:150)); shortening a slot does not automatically add a booking. US abdomen/pelvis room time has p50 38 minutes plus p50 five-minute documentation. ROADMAP criterion 13’s MR cap is justified by darkness after 16:30, which the new roster removes; criterion 14 targets a 07:30 backlog, not specifically takeover.  
    **Why it matters:** “18% wasted” counts only room time and ignores technician documentation. Forty-minute slots may increase technician congestion; changing lengths alone mostly creates gaps. Requiring old utilization/backlog bands can force the new scenario toward inappropriate behavior.  
    **Change:** Publish the actual repacked US template and check complete technician workload and waits. Define new scenario-specific utilization and service bands, distinguishing takeover from recurring morning backlog. Also correct the scope inventory: there are five named actions, plus an unspecified cancellation operation; the roadmap shift needs to account for the existing V0.5/V0.6 milestones.

## Unit-economics check

The scenario’s payer model uses mutually exclusive full-payment, short-payment and denial outcomes. Expected collection fractions are:

- Commercial: \(1-.07-.05+.05(.70)+.07(.50)=.95\)
- Medicare: \(1-.04-.02+.02(.80)+.04(.60)=.98\)
- Medicaid: \(1-.09-.04+.04(.70)+.09(.40)=.934\)
- Self-pay: \(1-.50-.20+.20(.50)=.40\)

Weighting payer mix and allowed-rate multipliers gives:

\[
E[\text{net revenue}]/\text{base rate}
=.45(1.6)(.95)+.35(.98)+.10(.75)(.934)+.10(.90)(.40)
=\mathbf{1.13305}.
\]

This follows [finance.go:60](/tmp/dt-review.VdCTC9/internal/sim/finance.go:60) and [established.json:260](/tmp/dt-review.VdCTC9/scenarios/base/established.json:260).

Weighting growth toward US/CT/MR can improve revenue per referral while also increasing technician and reading workload. **The premise is plausible; the permitted lever set has not yet been shown sufficient.**

## Answers to §12

1. **Roadmap:** Approve the staffing-first direction, after resolving the engine contracts and renumbering all displaced milestones.
2. **Sustainable levers:** Accept 15–30% referral growth as a premise, conditional on a source-specific feasibility sweep; do not guarantee the margin band beforehand.
3. **Quality and money:** Keep reimbursement/referrals revenue-neutral; add explicit service gates for successful management instead of premature referral dynamics.
4. **Hiring model:** Use deterministic published lead times and defined training requirements; a candidate pool adds complexity without addressing the demonstrated constraints.
5. **Radiologists:** Keep allocation and teleradiology only; explicitly restrict or price radiologist roster changes.
6. **Notice periods:** Reasonable gameplay defaults, provided guaranteed-hours obligations are defined and management is evaluated beyond T30.
7. **Teleradiology pricing:** Use the list as an illustrative experiment baseline, with retainer/night rules specified and substitution tested; do not call its anti-arbitrage property established.
8. **Scorecard weighting:** Report a metric vector plus minimum service constraints now; defer an arbitrary weighted composite.
9. **Session schema:** Prefer V2 for new records, with an explicit V1 reader and legacy verification path; a schema bump alone does not solve digest compatibility.

## What the draft gets right

- It follows the measured imaging and evening/weekend reading constraints.
- It preserves the struggling default and refuses to manufacture revenue or backlog.
- Deterministic recruiting, stable identities and authoritative action replay suit this simulator.
- Immediate visibility of future capacity and explicit displacement are good management mechanics.
- Separate service and financial results, paired seeds, published manifests and an explicit calibration-failure decision are the right foundations.
