# V0.13k lifecycle contract

Identity: `dreamteam.run-lifecycle/v3`. Machine contract: `analysis/alternatives/bindings_v1.json`, schema `dreamteam.evidence-bindings/1`. DRAFT, NOT LOCKED. Independent review PENDING. Owner protocol lock and live inference decisions: NO GO.

The [inventory](EVIDENCE_BINDINGS.md) is authoritative for every evidence relationship. The recorder and independent verifier consume its stage shapes, field types, hash grammar, limits and cleanup rules. The verifier imports no recorder logic. It reconstructs engine and workflow events through frozen implementations and compares typed canonical JSON; claimed verification labels never grant trust.

The inherited states, transitions, stop precedence, safe-point dispositions, call journal and completion seal retain their meanings. The seal format and `dreamteam.run-finalization/v1` rename commit point are unchanged from [V0.13j](../v13j/SAFETY_CONTRACT.md). The complete finalization subtree is checked byte-equivalent as JSON during preservation verification. No new recovery or resume protocol is introduced.

A successful draw result is persisted as `pending-draw.json` before ledger mutation, including the entire result and its canonical row hash. The handoff remains until both ledger row and commit transition are durable. A handled exception immediately before the frozen draw returns captures its completed result from the exception traceback and hands it off through the same path. Handoff clearing is directory-synced. Failed handoff or ledger candidates are retained. An unsealed failure report records the exact persistence stage, error, pending result and failed candidate names on a best-effort basis; the public recording error also retains this information. Any failed persistence poisons the archive: it cannot be sealed. Additional handoff/candidate/failure artifacts make an archive INVALID, preserving evidence for audit rather than asserting a terminal result.

Every valid cleanup records exactly three visits in this order: `before_cleanup`, `after_cleanup`, `before_finalization`, each once, in CLEANUP. The cleanup-entry transition is no later than `started`; the first visit precedes completion; completion precedes the last two visits; the final visit precedes the cleanup transition and seal. Interrupt events are an ordered nonduplicated subsequence of those visits, with identical state and timestamp, in addition to inherited STOP rules. Cleanup failure is recorded beside the primary stop; it never replaces it.

Aborted stage shapes are explicit in the machine contract. Setup/open failures retain only the fields possible at that point. Initial-digest and workflow failures retain their engine/call prefixes. Final-digest and engine-close stages require exactly one finished record or guard halt, together with their corresponding proposal, submitted batches, process, calls, engine log and digests. Every retained reconstructable event is replayed, even when its external failure cause is UNVERIFIED. Unknown draw evidence is explicitly unknown, never zero; the journal remains authoritative for dispatch counts and grammar. Unknown external causes do not excuse inconsistent retained data.

For each dispatch, the scheduled draw identifies its context. Its context call bound and per-draw cap apply directly to the journal independently of nullable draw call evidence. The run cap also applies, with an absolute 802-call ceiling. Hashes are lowercase hexadecimal SHA-256 strings; reconstructable bodies and requests must match their hashes and exchanges exactly.

Health response JSON rejects duplicate keys and nonfinite values under the existing invalid_json category (health-evidence-classification/v3). Health exceptions are classified only through imported trusted class objects, including wrapped reasons. Names in an exception object's module or qualified-name text grant no trust. Supported trusted health failures and all model-visible messages remain unchanged.

Acceptance: never accept false COMPLETE or contradictory PARTIAL; preserve completed evidence across handled failures; classify unrecoverable archives INVALID. Recovery from arbitrary power loss or forced termination before a durable handoff is not required. The existing seal process-crash semantics remain in effect.

When the draw call array is unknown, full analysis reconstructs the retained journal response prefix through the frozen workflow and compares each derived request hash. A null call array never excuses a contradictory reconstructable request. The missing draw result remains unknown.
