# Fault verification — matrix, real signals, loopback, witnesses, contradictions

Independent technical re-review PENDING. Scripted model replies, scripted HTTP
byte streams, genuine exception objects and localhost-only servers. No model
endpoint, no inference.

## Fault-injection matrix (`fault-matrix/matrix.json`, dreamteam.v13i-fault-matrix/v1)

Generated by [v13i_faults.py](../../analysis/alternatives/v13i_faults.py)
from the contract, not from earlier witnesses:

1. Three base scenarios run once each with a recording hook: **A** two
   completed draws, server observed, every read healthy (163 points);
   **B** the round health check before draw 2 answers unhealthy (135);
   **C** engine opening fails at draw 2 (161). Every point reached is a
   declared `(boundary, phase)`; an undeclared point is an error. All 73
   declared points are reached.
2. Every point of A, and the stop/cleanup/finalization points of B and C,
   is combined with every fault kind the contract declares for that
   operation and phase: exception, keyboard interrupt, transport failure
   (health read: a genuine refused connection through the production probe;
   model call: a failed exchange), persistence failure (EIO from the
   filesystem call), guard halt (the run clock passes the wall-clock stop).
3. Each case reruns the scenario with that single fault and records the
   recorder's result, the independent classification, stop code and state,
   completed draws, model calls, cleanup, aborted stage, marker, and the
   model-free replay analysis of every valid archive (or the analyzer's
   refusal of an INVALID one). The expected outcome is computed from the
   contract's `expectedRule` and the point's context.

**Result: 601 cases at 240 points (A 407, B 88, C 106 cases); 601 agree,
0 disagree.** Faults: exception 238, keyboard 238, persistence 118,
transport 5, guard halt 2. Expected rules: FAIL_CLOSED 452, HANDLED 102,
NO_ARCHIVE 34, CLEANUP_FAILED 6, HEALTH_STOP 3, GUARD_STOP 2,
WORKFLOW_EVIDENCE 2. Observed: INVALID 486 (every one refused by analysis),
PARTIAL 113 (every one replayed and analysed, comparisons suppressed),
COMPLETE 2 (only the two model-transport cases, where the failed exchange is
workflow evidence and the run legitimately completes). No fault produced a
COMPLETE archive otherwise; no persistence or finalization fault produced a
valid archive. Boundaries: run.json checkpoints at every transition 270,
FINALIZING marker 54, final manifest 54, ledger 36, failure event 36, marker
removal 30, health read 21, initial ledger 18, initial server state 18, draw
execution 18, session release 18, aborted artifact 18, draw guard 10.

The first full run of the matrix found a real defect (a stale "draw entered"
flag after a fault between draws made the aborted skeleton claim
`draw_unrecorded` instead of `draw_setup`); it was fixed and the matrix rerun.

## Real-process signals (`signals/results.json`, 19 cases, 19 agree)

[v13i_sigint.py](../../analysis/alternatives/v13i_sigint.py) delivers a real
SIGINT to a child process blocked at the named point (or has the child
signal itself), then classifies and analyses the archive: before, during and
after the first health check; before the draw; during engine opening; during
a model call; after the ledger write; during the ledger write; before the
manifest update; between draws; during a later health check; during cleanup;
during finalization (marker sync and final rename: deferred, archive
COMPLETE, child reports the deferred interrupt). Process termination: SIGKILL
during the initial health read, SIGTERM at the draw guard, SIGKILL during
cleanup and during the final write (all INVALID, marker kept where it was
written), and a self-delivered SIGINT after the ledger write (reconciled,
PARTIAL with the draw counted). A completed draw durable in the ledger is
never lost from accounting under a handled interrupt.

## Loopback (`loopback/results.json`, 11 cases on linux/x86_64, 11 agree)

[v13i_loopback.py](../../analysis/alternatives/v13i_loopback.py) runs on
horo with real sockets: healthy, explicit unhealthy, connection refused,
connection closed early (remote_disconnected), incomplete body
(incomplete_read), delayed within the timeout (COMPLETE), timeout, malformed
JSON, HTTP 503, healthy-with-error body (contradictory_body) and the server
disappearing between health checks (refused at the second round check, one
draw completed). Archives carry actual timestamps and fresh UUIDs; the
verifier refuses synthetic provenance; recorder, verifier and analysis agree
on every case.

## Regression witnesses (`witnesses/results.json`, 71 cases, 71 agree)

[v13i_witnesses.py](../../analysis/alternatives/v13i_witnesses.py)
re-expresses the earlier reviews' counterexamples against V0.13i:
DT13H-01 health matrix (16), DT13H-02 boundary interruptions (22), DT13H-03
final persistence and the failed-finalization comparison (7), V0.13g
lifecycle edges (4), V0.13g 21 partial probes, and a request-start
wall-clock halt. They pass as a consequence of the design; see
[gates/TEST_MAP.md](gates/TEST_MAP.md).

## Contradictory evidence (`mutations/results.json`, 69 mutants, 69 rejected)

[v13i_mutations.py](../../analysis/alternatives/v13i_mutations.py) alters
five genuine archives (COMPLETE with both arms; health stop; aborted workflow
with a recorded failed exchange; draw-limit halt; cleanup failure) and
re-seals every hash, mirror and binding a forger could recompute, so that only
the targeted contradiction remains. Each mutant must be INVALID with the
targeted invariant among its violations, and analysis must refuse it. The
suite covers the owner's list (completed draw with cleanup failure, unhealthy
initial server under COMPLETE, impossible engine-open evidence, impossible
call totals, duplicate completed draws, missing schedule entries,
contradictory stops, illegal transitions, inconsistent hashes, unsupported
terminal states), DT13H-05 timestamps (null, unparseable, impossible
calendar, reversed, out of order, missing, call times outside the draw), the
DT13H-01 health shapes, and file defects (marker, stray file, legacy stop
file, missing/truncated manifest and ledger, missing/mismatched failure event,
missing aborted artifact, missing initial state).

## Reproduce

    python3 -I -B analysis/alternatives/v13i_faults.py run --binary ./dt --scratch S --out matrix.json --jobs 12
    python3 -I -B analysis/alternatives/v13i_sigint.py run --binary ./dt --scratch S --out signals.json
    python3 -I -B analysis/alternatives/v13i_loopback.py --binary ./dt --scratch S --out loopback.json
    python3 -I -B analysis/alternatives/v13i_witnesses.py --binary ./dt --scratch S --out witnesses.json
    python3 -I -B analysis/alternatives/v13i_mutations.py --binary ./dt --scratch S --out mutations.json

Each output is byte-reproducible and compared with the committed file in the
horo gates; CI runs `test_v13i.py` (witnesses, mutations, real signals,
loopback and a matrix sample) on linux/amd64, linux/arm64 and darwin/arm64.
