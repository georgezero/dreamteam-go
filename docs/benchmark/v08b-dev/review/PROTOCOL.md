## Purpose

The review asks one question of each item: **does the evidence in the
item support the rule's output?** It is a check of the frozen
`dreamteam.decision-evidence/v1` outputs, not of any model.
* Whether a decision was good is not asked.
* Whether a model is better than another is not asked.

## The sample (frozen)

| | |
|---|---|
| Sample | `v08b-review-1`: 98 items ([manifest.json](manifest.json), [items.json](items.json), [items.md](items.md), [form.csv](form.csv)) |
| Source | the frozen v1 outputs (analysis/evidence/frozen-v1.json), regenerated by `analysis/evidence/review_package.py` from the replays. CI regenerates the sample and requires it to equal the committed one. |
| Frozen | before any review. `manifest.json` records the SHA-256 of `items.json`, and `review_analysis.py` refuses forms if the items differ. |

**Allocation.** A fixed number of items per rule and output:
* every supported finding of the rare rules (A: 5, C: 3; B has none);
* 10 supported findings each of D, E and F;
* unresolved findings of A (6), B (3, all of them), C (6) and F (2, all of
  them);
* 3 of the 9 insufficient-evidence cases;
* 4–6 consistent checks per rule (32 in all);
* 8 negative controls.

**Strata.** Within each cell, items are taken in turn from the strata of
recording group, model and prompt completeness. Each stratum is ordered
by SHA-256 of the seed and the item's identifier, with no random-number
generator, so the draw is the same everywhere.

**Order.** All items are listed in one seeded order that mixes rules and
outputs. The order carries no meaning.

**Negative controls** are reasons that mention an action (extend, hire,
terminate, cancel, teleradiology, allocation, roster, a policy) in which
the rules found no explicit statement of intention. The reviewer checks
that abstaining was right: that the reason really states no explicit
intention the rules should have read.

## What each item shows

* the identifier (a finding `de1-…`, a consistent check `rv1-…`, a
  negative control `nc1-…`);
* the recording, decision point and model;
* the whole reason, and the span the rule read;
* the proposed actions;
* the validation and execution of each action;
* what the rule checked: the statement, the amount and quantity, the
  fact, or the refused proposal and its occurrences;
* the public observation the rule used:
  * the staff names behind employee IDs;
  * the prompt excerpt where the observed value appears;
* the rule's output and its basis;
* the evidence completeness.

Each item names its sources: the recording line, the replay transcript,
the apply results, and the prompt's SHA-256. A reviewer who wants more
can rebuild the whole prompt (DECISION_EVIDENCE §4).

## Labels

One label per item, in `form.csv`:

| Label | Use when |
|---|---|
| `supported` | the evidence in the item supports the rule's output as stated: the finding holds, the check really is consistent, or the abstention (unresolved, no statement) is right |
| `unsupported` | the evidence contradicts the rule's output: a supported finding that is not a mismatch, a "consistent" check that is a mismatch, or an abstention where the reason states a clear, explicit intention the rule should have read |
| `ambiguous` | reasonable readers could disagree from this evidence |
| `insufficient_evidence` | the item does not contain enough to decide |

* **`comment`:** free text.
* **`correction`:** what the output should have been, if `unsupported`.

**Rules for the reviewer:**
* Judge the specific item, not the model, and not the rule's design.
* Do not use outcomes: a bad result is not evidence about a statement.
* Treat an explicit statement as the rules define it (DECISION_EVIDENCE
  §6.1). If you think the definition itself is wrong, say so in a
  comment, and label the item against the definition.

## Independence

A reviewer counts as independent only if all of these hold:
* they did not write, calibrate or tune the rules;
* they did not choose the sample;
* they did not see the developer's own review notes;
* they declare this in `reviewer.json` beside their completed form:

```json
{"reviewer": "name or role", "independent": true,
 "statement": "I did not write, calibrate or tune these rules, nor choose the sample."}
```

Two or more reviewers may label the same sample independently. Their
disagreements are reported per item.

No automated check, script, model or LLM may produce labels. An LLM
judge is excluded by the owner's decision.

## Analysis (after a completed review)

```
python3 -I -B analysis/evidence/review_analysis.py \
    --manifest docs/benchmark/v08b-dev/review/manifest.json \
    --form <reviewer A>/form.csv [--form <reviewer B>/form.csv] --out review-result.json
```

**What it reports,** per cell (rule/output):
* the number reviewed;
* the counts of `supported`, `unsupported`, `ambiguous` and
  `insufficient_evidence`;
* the number of items on which reviewers disagree.

**When it reports nothing:**
* a form is incomplete;
* a form has no independence declaration;
* the items differ from the frozen sample.

**What it never reports:**
* precision: the sample is stratified, not random, and small;
* recall: there is no labelled population of statements the rules
  missed.

The results are kept apart from the frozen rule outputs, which are never
changed by the review.
