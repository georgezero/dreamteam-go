# V0.13d review response

This responds to `docs/audits/v0.13d-independent-review.md`, committed
verbatim and separately (`e40e6c0`). The review covers the tree committed
as `2f89a03`.

**The review's verdict:** do not lock yet. It found 9 MAJOR, 3 MINOR and
2 NOTE findings. No end-to-end injection of a name or request ID was
reproduced; the typed forms were judged a typed grammar, not a sanitizer.

**The rule followed:** fix every confirmed defect; where a fix narrows
what a text or a measure means, implement the reading the owner's
decisions and the documents already state, and list it for the owner to
confirm.

## For the owner to confirm

* **F7, the primary scale.** D9 asks for "the difference in immediate
  final-action distributions" and lists the categories. The review showed
  that the arms' own labels are not a common scale. The fix keeps the
  owner's categories but defines them from the submitted batches, the same
  way in both arms: "alternative selected" becomes `listed_alternative` (the
  reply's operations with another candidate's staffing batch, whichever arm
  and whatever the reply called it), "no action selected" becomes
  `no_staffing_action`, "revision" becomes `other_batch`. Please confirm this
  reading, or choose the exact-batch distribution, also reported, as
  primary.
* **F3, `compared`.** It now means a correct citation of details actually
  sent. The alternative reading, a correct citation of any available
  value, is not used.
* **N1, D8.** The shared foot is now the same text in both arms. The
  treatment still lists the alternatives (that is the comparison) and may
  use one inspect call.

## Not changed

* **Pooling across models within an arm** (review §7): every request in a
  pooled session is read-only and every draw checks the digests; the review
  found no contamination.
* **The human presentation review and the budget approval** remain the
  owner's gates (N2). The driver still cannot run any protocol: there is no
  lock command and no live implementation.
