## Not fixed: needs an owner decision

**F4.** A proposal that terminates the same employee twice produces two
identical leave-one-out candidates.

**What happens now:**
* The engine refuses the proposal.
* `without_1` and `without_2` are the same batch.
* `BuildAgent` lists both.
* `BuildEvaluation` refuses the pair, because `Branch` refuses equal
  batches.

**Why it is not fixed:**
* The pinned rule text (`selection-v1.txt`) says to list each
  leave-one-out candidate, and the code follows it.
* Collapsing equal candidates, or skipping them, changes the rule and
  needs a new rule version and pin.
* That is a policy change, so it waits for the owner.

**Its reach:** it occurs only for a proposal the engine already refuses.
Until a decision, the case is listed in `docs/v13b/LIMITATIONS.md`.
