**DT13G-01 — MAJOR — Genuine health failures are rejected by the partial-run verifier.**

- **Location:** [v13g.py:875](/home/george/dt-audit-v013g-rereview/repo/analysis/alternatives/v13g.py:875); producer at lines 712/720; production health getter at [repeat_run.py:116](/home/george/dt-audit-v013g-rereview/repo/analysis/repeatability/repeat_run.py:116).
- **Failure:** The getter represents timeout/connection failures as `{"error":"TimeoutError"}` or `{"error":"URLError"}`. The driver correctly stops and saves `run.json` plus `stop-event.json`. The new verifier requires a nonempty `health.status`, rejecting that genuine evidence with **“health stop lacks evidence.”**
- **Evidence:** The same offline `URLError` state is accepted by V0.13f and rejected by V0.13g. [Reproducer](/home/george/dt-audit-v013g-rereview/scratch/lifecycle_edges.py), [results](/home/george/dt-audit-v013g-rereview/scratch/lifecycle-edges/results.json).
- **Why it matters:** An ordinary server outage leaves a recorded partial run unanalyzable. This is a new regression introduced by the stricter health-evidence rule.
- **Smallest fix:** Define and validate both supported unhealthy-status responses and explicit failed-health-read records, keeping their external cause unverified. Share the producer/verifier rule and test the production getter’s error shapes.
- **Human presentation re-review:** No model-visible wording change is inherently required. Add the corrected record-only partial example; the overall human-review requirement remains outstanding.
