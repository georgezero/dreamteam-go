**F1 repair:**

* **The change:** `consequences()` in `agents/llm/llm_agent6.py` now
  requires every field that a consequence is read from or identified by:
  * present, and not `null`;
  * of the engine's type: an integer ≥ 0 that is not a boolean or float,
    a real date, or non-empty text;
  * consistent: each termination's batch count equals the displacement
    list, and every entry is one the batch accounts for.

  A key given twice inside the preview answer also fails. llm-agent 6's
  engine reader, a subclass of llm-agent 3's reader that leaves llm-agent
  3 itself unchanged, marks such keys, and it refuses `NaN` and
  `Infinity`, which the engine cannot send. Any failure withholds the
  proposal as `consequences_unavailable`, before an acknowledgment is
  requested. The fields are listed in
  `docs/V0.12_CONSEQUENCE_INVENTORY.md` §4.
* **Unchanged:** the contract, the matching rules, the token algorithm,
  the request texts, and therefore the workflow and contract identities
  (`b9cb7982…`, `33c116da…`). The V0.12a scripted evidence regenerates
  byte-identical, and every preview answer recorded from the real engine
  still reads without a problem. No version change of the contract or
  record was needed.
* **Regression tests:** `agents/llm/test_llm_agent6_fields.py`, 18 tests,
  each built from a real recorded engine answer.
  * **Before the repair:** 15 of the 18 failed or errored (01–13, 16 and
    18). The two valid
    cases (14, a zero value; 15, a complete preview) and the final-check
    case (17) passed, because the existing behaviour already handled
    them. Test 12 errored because the reader it calls did not exist yet.
  * **After the repair:** all pass.
* **F4 (hire coverage):** `internal/bench/llm_agent6_hire_test.go` now
  runs a hire on the real engine. It checks the exact fee and
  earliest-exit cost, the target identity, and that an empty or wrong
  acknowledgment is withheld with the session unchanged. It also checks
  that an accurate acknowledgment is submitted after an agreeing final
  check and applied, and that replay is byte-identical.
* **Version:** 0.12.0-dev.2. 0.12.0-dev.1 is registered as session batch
  mode `v0.12_dev1`, with a fixture made by a 0.12.0-dev.1 binary.
