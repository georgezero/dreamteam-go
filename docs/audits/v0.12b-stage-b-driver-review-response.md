# V0.12b Stage B driver review: maintainer's response

**The review:** [v0.12b-stage-b-driver-review.md](v0.12b-stage-b-driver-review.md),
of commit c9ba751, committed verbatim at 1fb619c. It found no Blocker and
gave GO for locking the protocol, on two conditions:
* D1–D4, D9 and D10 are settled before the lock commit;
* D5–D8 and D11–D13 are fixed or recorded.

**This response** covers every finding, in a commit of its own, before the
lock. None of the fixes changes either agent or the approved design. They
change only the driver's classification and records, its checks, and the
documents.

| ID | Severity | Decision | Change |
|---|---|---|---|
| D1 | Major | Fixed: one rule for "unchanged" | Class A and A's "proceeded" now compare actions by canonical content in any order, as the proposal outcome does (`unchanged()`). A resubmission that only reorders R is A_proceeded, flagged `reorderedOnly`. The extra request llm-agent 6 makes for it stays visible in `modelCalls`. The tables show a "Reordered only" column for both arms. PROTOCOL.md §5 states the rule. |
| D2 | Minor | Fixed | `finalProposalValid` (renamed from `lastProposalValid`) is the last validation of the last proposal's actions. A valid, unchanged proposal whose acknowledgments were rejected is valid. PROTOCOL.md §5 and DRIVER.md §5 updated. |
| D3 | Minor | Wording aligned with the code | "Accurate before a change" means the acknowledgment states exactly the consequences of the request it answered (the latest request shown), as llm-agent 6 matches it. PROTOCOL.md §5 and DRIVER.md §5 updated. |
| D4 | Minor | Fixed | Every class D draw records `dReason`. That is the agent's withheld reason, or, where the agent records none, `revision_refused`, `invalid_reply` or `failed_request`. The B table's last column is now "Why D". PROTOCOL.md §5 lists every reason. |
| D5 | Minor | Fixed | Replay recomputes usage, finish reason and served model from each hash-checked body and refuses any difference. |
| D6 | Minor | Fixed | A transport that raises is recorded as a call (`client: <type>: <message>`) and counted, then the exception goes on. The unfinished draw (its calls and engine requests so far) is written to `live/aborted-draw.json`, and `run.json` names `drawAborted`. `modelCalls` equals the recorded calls. |
| D7 | Minor | Fixed | Ctrl-C during a draw takes the same path: `stopped: operator`, and the unfinished draw is written to `aborted-draw.json`. |
| D8 | Note | Wording | PROTOCOL.md §4 and DRIVER.md §3 now say the stop cannot be overrun by a model request. Engine time after the last request (about a minute at most on the Pi) is not bounded. |
| D9 | Minor | Settled in the lock commit | `lock.files` will enumerate every executed or read file the review lists. The schedule is pinned by `lock.scheduleEntriesSha256`. `check_schedule` now also checks `schema` and `protocolSha256` (for `check` and `run`). PROTOCOL.md §8 states the lock commit's order: write the lock, regenerate `schedule.json`, regenerate the mock run, update README's hashes, CI green. |
| D10 | Minor | Fixed | `check` exits 1 when the lock does not hold, unless `--unlocked-ok` is given. CI uses `--unlocked-ok` only until the lock commit, and the plain `check` from then on. |
| D11 | Note | Fixed | `check_run_doc` checks `run.json` against the rows: the completed count, `drawInterrupted` and the status against `stopped` and coverage. |
| D12 | Note | Fixed | The driver's harness checks each answer's `protocol` as well as its id. |
| D13 | Note | Recorded | DRIVER.md §8 states that `previousExecution` is always null and request ids restart per draw, and that neither enters a prompt, message or classification. |

## The focused re-review

**The re-review:** [v0.12b-stage-b-driver-rereview.md](v0.12b-stage-b-driver-rereview.md),
of 81bb0cf, committed verbatim at 75038a3.
* **Verdict:** GO for writing the lock, with conditions.
* **D1–D13:** all closed except D9, which is settled by the lock itself.
* **New findings:** R1 (Major), R2–R4 (Minor), R5 (Note).

**What was done** (in a commit of its own, before the lock):

| ID | Severity | Change |
|---|---|---|
| R1 | Major | "Unchanged" is now truly canonical. `same_content()` compares `canon()` of each action, with keys sorted and in any order, for the outcome (a driver-local `response_of`), class A and A's "proceeded". Key order inside an action is never a change. `reorderedOnly` still flags a reordered list. PROTOCOL.md §5 says so. |
| R2 | Minor | Nothing is submitted when the agent's outcome is `fallback`, even with a used attempt. A `state_changed` withholding is therefore `withheld` / D, with `dReason state_changed`. Listed in §5. |
| R3 | Minor | `body_fields()` derives usage, finish reason and served model from any body. A reply whose JSON is not an object is recorded and handled by the agent (a retry), and `modelCalls` equals the recorded calls. |
| R4 | Minor | §8 names the pinned documents (PROTOCOL.md, DRIVER.md, PROCEDURE.md) and puts README.md, the audits and PROGRESS.md outside the lock. |
| R5 | Note | Any other `BaseException` sets `stopped: driver` before it is re-raised. `check_run_doc` refuses a COMPLETE `run.json` that names an aborted draw. §5's "A's matching classes" now lists `failed`. |

**Tests:** `test_stage_b.Rereview` adds 4 tests, each failing on 81bb0cf
and passing after the change. The suite is now 51 tests.
