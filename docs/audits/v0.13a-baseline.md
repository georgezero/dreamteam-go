## 3. Mechanics check provenance

This check was run once, on the Raspberry Pi (linux/arm64, go1.27.1),
with a binary built from this tree before any V0.13a edit. It uses
existing commands only. It is not an evaluation: no model, no reserved
or holdout seed, no clinical suite.

**The decision-point probe** (`dreamteam agent -stdio -scenario mini
-seed 52`). The requests were:
1. `advance` to 2026-10-13T07:00:00;
2. `digests`;
3. `validate` of `[{"type":"terminate","employee":"E04","lastDay":"2026-10-27"}]`;
4. `preview` of the same batch;
5. `digests`.

The two `digests` answers were identical.

**The branches:**

```
dreamteam run -scenario mini -seed 52 -days 45 -actions branchA.actions.json -save branchA.session.json -verify-replay -format json
dreamteam run -scenario mini -seed 52 -days 45 -actions branchB.actions.json -save branchB.session.json -verify-replay -format json
dreamteam verify branchA.session.json   # ok 808d448b79de811f9371a6e2a2d08aaa4af1be990111fdba1c04d33ac3206b3c
dreamteam verify branchB.session.json   # ok 8618a73ec195af2bc65610834f1c926fb27987d12dc33ee1bbd0b1141e3cbdd3
```

**The inputs:**
* `branchA.actions.json`: `[{"time": "2026-10-13T07:00:00",
  "actions": [{"type": "terminate", "employee": "E04", "lastDay":
  "2026-10-27"}]}]`
* `branchB.actions.json`: `[]`

**Results:**
* A second run of A gave a result identical in every field, apart from
  the replay block, which it did not request.
* 130 of the 204 result fields differ between A and B.
* `demand.received` is 2,224 in both.
