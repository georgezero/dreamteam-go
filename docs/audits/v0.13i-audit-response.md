# V0.13i lifecycle redesign response to the V0.13h re-review

Baseline: a4d7204c14f36977fee044b3d1a17518d58cc02c (V0.13h plus the verbatim
re-review). The four committed independent audits remain verbatim. This is
implementation evidence, not the independent technical re-review, which is
PENDING. Human presentation review is PENDING and limited to the 93
unchanged model-visible transcripts. Protocol lock, live inference and the
V0.13.0 release remain NO GO.

The owner directed that DT13H-01 to DT13H-04 be fixed through a lifecycle
redesign and DT13H-05 through timestamp validation, not by patching
individual witnesses. The versioned contract
[dreamteam.run-lifecycle/v1](../v13i/LIFECYCLE.md) was written and committed
before any recorder change. The recorder (`v13i.py`) changes state only
through its transition table; the verifier (`v13i_verify.py`) loads the same
contract, does not import the recorder, and derives the archive's state from
the persisted files.

The fault matrix is generated from the contract's declared operations, phases
and fault kinds at every point the recorder reaches in three base scenarios;
expected outcomes come from the contract's `expectedRule`. The previous
reviews' witnesses pass as regression checks; they were not the design.

Model-visible content is unchanged: the decision workflow, parser,
presentation, view, selection, system instruction, canonicalization,
simulator, session, API and scoring are byte-identical; all 93 transcripts and
7 active static assets match the frozen human-review manifest. The 262-draw
schedule, 802-call ceiling and primary estimand are unchanged. The engine
remains 0.13.0-dev.2.

Not provided, by design or pending an owner decision: post-hoc recovery or
finalization of an archive left unfinalized by a hard kill (such archives are
INVALID with their committed files intact); any guarantee against power loss
or filesystem reordering.
