**4. Seal commit and durability**

The seal commit mechanism is substantially sound for its **process-crash** claim:

- The verifier requires a seal; changing manifest state cannot substitute for it.
- Required archive writes precede seal creation.
- The seal file is synced before its atomic rename.
- Tested failures before rename leave INVALID archives.
- SIGKILL immediately after successful rename leaves the completed archive intact.
- A rename wrapper that succeeds and then raises is recognized as committed.
- Persistent post-commit directory-sync failure is reported publicly without modifying the archive.

The best-effort directory fsync is consistent with the owner’s conditional requirement **for the claimed process-crash guarantee**: directory persistence across power loss is not required to survive termination of the recording process. It would not establish a power-loss durability guarantee.

I found no new false COMPLETE caused by the seal commit point itself. **A valid seal over contradictory content still passes in the findings below.**

**5. Safe-point interrupts and known-call accounting**

The minimal SIGINT handler and deferred processing fix the original interruption windows. The complete **326-case real-process signal suite reproduced byte-for-byte**, including source-line SIGINT, process-group SIGINT, external SIGKILL, and SIGTERM cases.

Independent tests also confirmed:

- Group SIGINT reaches the recorder while its engine remains alive.
- Normal cleanup subsequently closes the engine.

Dispatch intent conservatively means “may have been sent.” It should not be interpreted as proof that the transport was invoked.

The remaining evidence-preservation defect concerns **completed draws**, not the original SIGINT handler: DT13J-04 demonstrates that rejection alone does not satisfy the owner’s rank-4 requirement.

**DT13J-01 — BLOCKER — Aborted-draw verification accepts retained semantic contradictions.**

Location: [field checks](/home/george/dt-audit-v013j-review/repo/analysis/alternatives/v13j_verify.py:534) and [aborted verification bypass](/home/george/dt-audit-v013j-review/repo/analysis/alternatives/v13j_verify.py:1023).

I changed a valid digest value to contradict the engine response, substituted the abandoned proposal as the submitted batch, and erased call accounting while retaining the recorded exchange. All passed full analysis as PARTIAL.

This violates **owner rank 2**. The external failure’s unverifiability does not make retained workflow evidence unverifiable.

Smallest fix: enforce cross-field bindings and replay all reconstructible evidence at each aborted stage; require the applicable record/halt exclusivity. Keep only the external cause unverified.

**DT13J-03 — BLOCKER — Unknown draw evidence bypasses the context call bound.**

Location: [conditional bound checks](/home/george/dt-audit-v013j-review/repo/analysis/alternatives/v13j_verify.py:879).

When `calls` is null, the context-specific bound is skipped. Journal validation applies only the global per-draw bound. A re-sealed `draw_unrecorded` archive with **four calls for S1-a, whose bound is three**, passes full analysis as PARTIAL. A nonhexadecimal 64-character request “SHA-256” also passes in this path.

Smallest fix: derive context bounds from scheduled draw identities and apply them directly to journal dispatch counts; validate journal hash grammar independently of draw-call availability.

**DT13J-04 — MAJOR — Persistence failure deletes already completed draw evidence.**

Location: [temporary-file cleanup](/home/george/dt-audit-v013j-review/repo/analysis/alternatives/v13j.py:475), [abandon handling](/home/george/dt-audit-v013j-review/repo/analysis/alternatives/v13j.py:684), and [matrix preservation check](/home/george/dt-audit-v013j-review/repo/analysis/alternatives/v13j_faults.py:331).

A completed draw is present in `Recorder.pending`. A single injected ledger fsync failure—or a close error **after successful fsync**—causes `_persist` to unlink its temporary file. The resulting archive has zero completed rows and no retained candidate draw. Its one call remains journaled.

The archive correctly classifies INVALID, but this is **owner rank 4, MAJOR**, not merely rank-3 availability loss. An exception immediately before `run_draw` returns also loses completed evidence and produces a sealed `draw_unrecorded` PARTIAL.

Smallest fix: retain failed ledger candidates and preserve completed pending evidence through error handling; establish a durable completion handoff and test it. Do not silently narrow “completed draws” to “previously committed rows.”

Witness: [boundary script](/home/george/dt-audit-v013j-review/scratch/undeclared_boundaries.py), [captured completed evidence and outcomes](/home/george/dt-audit-v013j-review/scratch/boundary-summary.json).

**DT13J-05 — NOTE — “Exact class” normalization actually trusts qualified class names.**

Location: [exception normalization](/home/george/dt-audit-v013j-review/repo/analysis/alternatives/v13j.py:154).

A custom `ValueError` subclass named `builtins.OSError` is normalized as a network failure, wrapped or unwrapped, and produces accepted PARTIAL evidence claiming that family.

This requires an in-process impostor class; it is **not a demonstrated network-input attack or an additional release blocker**. It does contradict the stronger exact-class claim.

Smallest fix: map actual trusted class objects to families, then serialize their names.
