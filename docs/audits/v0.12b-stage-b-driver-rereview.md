## 4. New findings

Severity: **Blocker** (must be fixed before the lock), **Major**, **Minor**,
**Note**. Every witness below was executed.

### R1 — "Canonical content" is not canonical: an acknowledgment reply that repeats R with its keys in another order is counted `revised` / `B_revised` — **Major**

* **Witness (executed, RR1 "D1'"):** arm B on the scripted engine,
  proposal `[FIRE]`; reply: the same action with its keys in reverse order
  (`dict(reversed(FIRE.items()))`, equal as a dict) and an accurate
  acknowledgment of R. llm-agent 6 accepts it as the answer to R's request
  (`A6.same` is key-order free), the final check agrees, and it is
  submitted. Result: `outcome revised, class B_revised, reorderedOnly
  False, accurateBeforeChange False, submitted True`, while
  `finalActionsKey` equals the proposal's canonical key (so
  `distinctDecisions` says 1 and B − A's "same action content" says yes).
  Arm A, proposal `[STAFF]`, review reply with reversed keys: `outcome
  revised, preview.class revised`.
* **Evidence:** `A4.same_actions` sorts `A3.compact(x)` per action, and
  `compact` is `json.dumps` without `sort_keys`: it is sensitive to key
  order inside an action, unlike `canon` (used for `finalActionsKey` and
  `actionContent`) and unlike `A6.same`. PROTOCOL.md §5 now says class A
  and the outcome compare "by canonical content, in any order", which the
  code does not do for keys. At c9ba751 the same input gave `outcome
  revised` with `class A_proceeded` (the mirror image of D1); the
  remediation's single rule made the class follow the non-canonical side.
  A model restating R in its acknowledgment reply with another key order
  is at least as plausible as reordering a list, and the draw would be
  counted as a revision in the central table and in B − A.
* **Fix (one line, before the lock, since `stage_b.py` is pinned):**
  canonicalize before llm-agent 4's rule, e.g. in `classify` compare
  `json.loads(canon(initial))` with `json.loads(canon(final))` (or give
  `unchanged()` and the outcome a driver-local `same_actions` over
  `canon(x)`), keep `reorderedOnly = same and not A6.same(final, actions)`
  (false here, as llm-agent 6 saw no change), and say in §5 that key order
  inside an action is not a change.
  `test_kept_whatever_the_recorded_key_order` covers only the stored
  proposal's key order, not a reply's; add the reply case.

### R2 — A `state_changed` withholding is classified `kept` / `A_proceeded` with nothing submitted — **Minor**

* **Witness (executed, RR1 "invariant"):** arm B, proposal `[FIRE]`, an
  accurate acknowledgment; a session whose `digests` answer drifts from
  its 6th request on. The agent accepts the acknowledgment, then finds the
  digests changed before submitting: `record.outcome fallback`,
  `withheld.reason state_changed`, `batches []`, `final.attempt 2`.
  `classify`: `outcome kept, class A_proceeded, submitted False,
  dReason None`.
* **Evidence:** `classify` takes `final` from `rec["final"]["attempt"]`,
  which llm-agent 6 sets to the used attempt even when it then withholds
  on `state_changed` (`llm_agent6.py` lines 800–806); the outcome rule
  tests `final is not None` before `rec["withheld"]`. §5 calls every
  fail-closed withholding "withheld" and D "nothing was submitted, and the
  model did not abandon"; its D list and `d_reason` do not name
  `state_changed`. On a pooled read-only session the digests cannot drift
  (the first review's W4), and the driver would stop at the next draw's
  state check, so the path is unreachable by design; it is a definitional
  gap in a pinned file, not a live risk.
* **Fix:** derive "nothing submitted" from `rec["outcome"] == "fallback"`
  (or `rec["withheld"]`) rather than from `final.attempt`; list
  `state_changed` in §5's D reasons.

### R3 — A 200 reply whose JSON is not an object is counted but not recorded, and aborts the draw — **Minor**

* **Witness (executed, RR2):** a transport returning `(200, "null", None)`,
  `(200, "[]", None)` or `(200, '{"choices":[null]}', None)`. Result: the
  run stops as `driver` ("draw 2: AttributeError: 'NoneType' object has no
  attribute 'get'"), `aborted-draw.json` holds 0 calls, `run.json`
  `modelCalls 1`: the D6 claim "`modelCalls` always equals the recorded
  calls" fails by one. `A3.completion` reads each of these bodies as
  `response_shape`, so the agent itself would have retried.
* **Evidence:** `PointModel.call` increments `limits.calls` and then calls
  `RR.response_fields(body)` before appending the call; `response_fields`
  catches only `ValueError`, and `d.get` / `ch.get` raise `AttributeError`
  on a non-dict. The `try` added for D6 wraps only the transport.
  Pre-existing at c9ba751 (not introduced by the remediation), unlikely
  from the oMLX server, possible from a proxy.
* **Fix:** derive the fields defensively (`try … except (ValueError,
  AttributeError, TypeError): parsedBody False`), or append the call
  before deriving them.

### R4 — §8's lock order works only if `README.md` is outside `lock.files`; §8 should say so — **Minor** (for the lock commit)

* **Evidence (files read):** `docs/benchmark/v12b-dev/README.md`'s hash
  table lists `protocol.json`'s own SHA-256 (circular if README.md is
  pinned) and the SHA-256 of `schedule.json` and
  `fidelity/mock-run/decisions.json`, which §8's order regenerates after
  the lock is written. §8 pins "this protocol's documents" without naming
  them. The other embedders of the protocol's hash are `schedule.json`
  (pinned by entries, settled), `mock-run/run.json` and `decisions.json`
  (regenerated, not pinned). `fidelity/fidelity.json`, `fidelity.md`,
  `mock-run/live/draws.jsonl`, PROTOCOL.md, DRIVER.md and PROCEDURE.md do
  not embed it, so the fidelity run need not be regenerated and CI's
  `cmp` of `fidelity.json` holds after the lock.
* **Fix:** name the pinned documents in §8 (PROTOCOL.md, DRIVER.md,
  PROCEDURE.md) and state that README.md, the audits and PROGRESS.md are
  outside the lock. Otherwise the order is workable: the schedule's
  entries do not depend on `lock` or `status`, so
  `scheduleEntriesSha256` is stable across the lock, and `mockrun` reads
  `schedule.json` through `check_schedule(…, None)`, which is why the
  schedule must be regenerated before the mock run, as §8 says.

### R5 — A `SystemExit` or `GeneratorExit` during a call leaves `stopped` null; `drawAborted` is not cross-checked — **Note**

* **Witness (executed, RR2):** a transport raising `SystemExit(3)` or
  `GeneratorExit` on the second call. The call is recorded (`client:
  SystemExit: 3`) and counted, `aborted-draw.json` is written, the
  exception leaves `run()` (not swallowed, as required), and `run.json`
  is PARTIAL with `drawAborted 2`, `modelCalls` equal to the recorded
  calls, and `stopped: null`. `check_run_doc` accepts it (a shortfall),
  and also accepts a COMPLETE `run.json` with `drawAborted: 2`.
* **Evidence:** `run()` sets `stopped` only for `KeyboardInterrupt` and
  `Exception`; nothing in the driver or the client raises `SystemExit`
  inside a transport call, so this is unreachable in practice. PROTOCOL §4
  says a PARTIAL `run.json` carries "the stop".
* **Fix (optional):** set `stopped = {"code": "driver", …}` for every
  `BaseException` before re-raising; in `check_run_doc`, require
  `drawAborted` to be null on COMPLETE.

### Clean

* **`unchanged()` and the invariant in `ack_class`:** the guard "same
  without an accepted acknowledgment" cannot fire on a list reorder: a
  reordered resubmission is a new proposal to llm-agent 6, assessed and,
  qualifying, acknowledged before submission (RR1: both acknowledgment
  entries present, the second accepted). `reorderedOnly` is false in
  every other case (RR1, all cases; the committed mock run, 0 of 44).
* **`finalProposalValid`:** every RR1 case gives the value §5 defines;
  the committed mock run has 25 of 44 valid, the field present on every
  draw and in both arm summaries.
* **`d_reason`:** every D draw has a reason; the agent's reason wins when
  present (RR1, six cases); the committed mock run's one D draw has
  `dReason == acknowledgment.withheld`.
* **`BaseException` handling:** `KeyboardInterrupt` → `operator`;
  `Exception` → `driver`; `SystemExit`/`GeneratorExit` re-raised after the
  record is written (R5 for `stopped`); the transport's exception is
  recorded before it propagates; `partialDraw` carries the calls and the
  engine log so far; `modelCalls` equals the recorded calls in every case
  except R3.
* **Replay:** the body-derived fields are recomputed from the verified
  body; timeouts and HTTP errors (`body ""`) derive to `None` and match;
  a `client:` call cannot reach replay.
* **`check_run_doc`, `check_schedule`, the exit code, `--unlocked-ok`,
  the protocol check:** as the table says; the committed mock run,
  schedule and protocol pass every new check.
* **Documents:** PROTOCOL.md §4, §5 (apart from R1's "canonical" and R2's
  missing reason), §8 (apart from R4) and DRIVER.md §1, §3, §4, §5, §8
  describe the code as it is. §5's "A's matching classes" omits `failed`,
  which the code and DRIVER §5 have (wording only).
