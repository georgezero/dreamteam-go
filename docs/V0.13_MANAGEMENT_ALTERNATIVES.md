## The question

**What V0.13a asks:** can the existing engine represent and compare,
exactly, the meaningful alternatives to an irreversible or financially
consequential action, before it is taken?

**The first case studied:** terminate an employee versus keep the
employee.

**The answer:**
* **Yes, for exact immediate consequences.**
  * The preview reports a termination's direct terms exactly.
  * The observation reports what keeping the employee continues to
    cost.
* **Yes, for deterministic projections, by rebuilding.**
  * Two branches can be rebuilt exactly from one decision point and
    advanced under a declared continuation.
  * Every digest can be verified.
  * Branches cannot be copied in memory.
  * The engine's keyed randomness gives both branches the same
    exogenous world.
* **No, for what the engine does not model.**
  * Examples: morale, clinical outcomes, the employee's own choices.
  * These are listed as unavailable, never estimated.

## Findings

1. **Every action has a meaningful no-action alternative.** Every
   alternative proposed is an existing action with existing parameters.
2. **A termination's direct terms are exact.** The preview reports, as
   engine facts:
   * last day, end date and notice;
   * severance and its payday;
   * contract pay to the last day;
   * displaced bookings;
   * voided items.
3. **Keeping the employee is not free.** The weekly guarantee
   ($1,975.00 in the example) and the severance exposure continue. The
   engine has no resignation, so an hourly contract ends only by
   termination.
4. **The preview does not report capacity lost by a termination-only
   batch (G1).** In the example, 0 bookings were displaced, yet the
   45-day projection showed 177 more orders lost. The cause was
   capacity that had never been booked.
5. **Exact branching works by rebuilding, not copying.** The mechanics
   check:
   * saved, replayed and verified both branches;
   * reran one with an identical result;
   * showed identical demand (2,224 orders) in both.
6. **Projections use the realized future.** They are exact under their
   continuation. They are oracle information, and belong to evaluation,
   not to the agent's presentation.
7. **Inspection and comparison can be made observable:**
   * an `inspect` request;
   * verified citations;
   * decision sensitivity in paired cases.
   The model's explanation is never scored.

**GO for a limited V0.13b**, deterministic and with no live inference:

1. **E1–E3 (read-only, in `internal/session`):**
   * a branch builder from a record;
   * branch identities;
   * a comparison reader.
   * Tests: identity, no-op sensitivity (accrual), replay on arm64 and
     amd64, common exogenous draws.
2. **The contract:** `dreamteam.management-alternatives/v1`, with
   audiences `agent` (A1, A2, C) and `evaluation` (adds B), and
   fail-closed field checks.
3. **The candidate rule:** `dreamteam.alternative-selection/v1`, with
   replay checks.
4. **The presentation:** the template, fixed and hashed, with tests that
   every number equals its engine field. It is not sent to any model.
5. **Scripted cases:** paired cases for decision sensitivity, built from
   real engine states. There is no live model.

**E4** (decided: approved narrowly by the owner, see V0.13b).
* E4 is an opt-in, read-only `slotsClosed` for termination-only
  previews.
* It touches the preview API, though not its default output.
* Without it, G1 is closed only by branch reads.

**NO GO:**
* live inference;
* any agent workflow shown to a model;
* multi-day evaluation;
* any change to simulator mechanics, accounting, schemas or scoring.

These wait until V0.13b is reviewed and an owner-approved protocol is

**What V0.13b established:**
1. **Branching.** Every branch is a fresh replay of the decision-point
   record, then the alternative's batch, then no further action. Each
   branch is verified, and each is replayable on its own. Records under
   earlier rules are refused.
2. **Shared exogenous world.** Orders received and walk-ins were
   identical in every pair tested.
3. **Accrual timing.** An accepted batch with no material effect
   changes no reported metric.
4. **Slots closed.** The report equals, slot for slot, what a committed
   termination closes. It is capacity, not demand.
5. **The audience boundary.** The agent audience cannot hold class B
   values; projections exist only in the evaluation audience.
6. **Scripted sensitivity.** On real engine states, a result changes
   exactly where a scripted rule uses the fact that changed.

**What V0.13d establishes:**
1. **The boundary is typed (D7).** A model is never shown the comparison,
   only a view made from it after `DecodeAgentAt`: neutral references,
   closed enumerations, numbers, dates and fixed text. Hostile names and
   request IDs never reach a turn, and anything unexpected fails closed.
2. **The arms share their wording (D8).** Both get the same head ("Nothing
   has been applied yet") and foot; the treatment adds the comparison.
3. **A workflow and a driver exist, with no model.** The workflow is
   llm-agent 5's validation-first, unchanged, then the engine's turn. The
   driver runs both arms from the same state, request and proposal, and
   replays every draw without a model. 65 scripted fidelity cases pass.
4. **Operations batches are preserved (D10)** with select, replaced by a
   revision, dropped by abandon; each batch validated alone.
5. **A smaller draft:** 262 draws, at most 802 calls, justified by the
   V0.10–V0.12 repeatability evidence. Not locked.
